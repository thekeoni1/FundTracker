# FundTracker session prompts

One prompt per work session, each a record of what was asked for as of its date. What actually happened is in PROGRESS.md. Each prompt is self-contained: paste it into a fresh Claude Code session in the FundTracker folder and it loads its own context before doing anything.

Rules of use:

- Do not start session N+1 until session N's exit criteria are met and recorded in PROGRESS.md.
- Every session begins by reading PLAN.md, PROGRESS.md and docs/edgar-formd-reference.md, and ends by updating PROGRESS.md.
- Tests never touch the network. Real filings go into tests/fixtures.
- One commit per numbered step, in order. Plain prose, no em dashes, in every doc and user-visible string.

## Session 0. Scaffold and EDGAR client (WP0)

Read PLAN.md (sections 5, 9 WP0, 10 and 11), PROGRESS.md, and docs/edgar-formd-reference.md section 1 first. This session builds the project skeleton and the HTTP client only. No parser, no database, no UI.

1. Create the project: `pyproject.toml` with `src` layout and package `fundtracker`, pinned `requirements.txt` (requests) and `requirements-dev.txt` (`-r requirements.txt`, pytest, pytest-timeout), `.gitignore` covering `data/`, `.env`, `venv/`, `__pycache__/`, `.pytest_cache/`. Create a venv, install editable, confirm `python -c "import fundtracker"` works. `git init` and commit.
2. `src/fundtracker/config.py`: load `FUNDTRACKER_USER_AGENT` from a `.env` file in the project root (and the environment), fail with a clear message if it is missing or still a placeholder, expose `DATA_DIR` (default `./data`), `RAW_DIR` (`data/raw`), `DB_PATH` (`data/fundtracker.db`), `RATE_LIMIT_PER_SEC` (default 5). Write `.env.example`. Commit.
3. `src/fundtracker/edgar/client.py`: a class wrapping `requests.Session` with the SEC headers (User-Agent, Accept-Encoding gzip deflate), a token-bucket limiter at the configured rate, retry with exponential backoff on 429, 403 and 5xx (max 5 tries, then raise), a 30 second timeout, and `get_cached(url)` that stores the body under `RAW_DIR` keyed by a hash of the URL plus a readable suffix and serves it on later calls; `get(url)` bypasses the cache. Add a `__main__` that fetches one URL and prints the body, reporting whether it came from cache. Commit.
4. `tests/test_client.py`: patch `requests.Session.request` (or the session's `get`) and assert: headers are set; N calls take at least (N-1)/rate seconds with a fake clock; 429 then 200 yields one retry; 5 consecutive 500s raise; a cached URL is requested once across two calls. No network. Commit.
5. Append the session entry to PROGRESS.md (shipped, test count, open questions). Commit.

Constraints: match the stack in PLAN.md section 5 (requests, not httpx; venv, not uv). Keep dependencies to requests plus the test tools. Do not fetch anything from EDGAR inside tests. The live smoke check in the exit criteria is run by hand, once.

Exit criteria: `pytest` green with no network; `python -m fundtracker.edgar.client https://www.sec.gov/Archives/edgar/data/2158817/000215881726000001/index.json` prints the folder JSON and a second run says it was served from cache; five commits in the order above; PROGRESS.md updated.

## Session 1. Form D XML parser, schema and repository (WP1)

Do not start until PROGRESS.md open question 4 (the WP0 live smoke check) is closed. Read PLAN.md (sections 6, 7.2, 9 WP1), PROGRESS.md, and docs/edgar-formd-reference.md sections 2 and 5 first. This session turns one `primary_doc.xml` into rows in SQLite. No index discovery, no data set loader, no scoring, no UI.

1. Fixtures. Write `scripts/fetch_fixture.py` that takes a CIK and accession number, fetches `primary_doc.xml` through `EdgarClient.get_cached`, and saves it as `tests/fixtures/formd/<accession>.xml` with a one-line entry in `tests/fixtures/formd/README.md` saying what the fixture exercises. Collect twelve real filings covering: the Axiaris hedge fund new notice (CIK 2158817, accession 0002158817-26-000001); the VC fund with an entity related person encoded as `firstName="-"` (CIK 2081663, accession 0002081663-25-000001); a `D/A` amendment with `previousAccessionNumber`; a 3C.7 fund; an Other Investment Fund with a 3C exemption; a Private Equity Fund; a non-fund issuer (industry group other than Pooled Investment Fund, with a revenue range); a filing with co-issuers in `issuerList`; one with `salesCompensationList` recipients, including a `statesOfSolicitationList`; one with two or more signatures; one with `yearOfInc/yetToBeFormed` or `overFiveYears`; and two filings with a schema version other than X0708, found by reading `form.YYYYMMDD.idx` for a 2010 date and a 2015 date from the daily index (reference section 3) and picking a `D` row from each. Use the client, not raw requests. Commit the fixtures and the script.
2. `src/fundtracker/model.py`: frozen dataclasses mirroring the raw tables in PLAN.md section 6: `Filing`, `Issuer`, `Offering`, `RelatedPerson`, `Recipient`, `Signature`, and a `FormDFiling` container holding one `Filing`, a list of `Issuer` (primary first), one `Offering`, and lists of the rest. Keep verbatim text fields and add the numeric shadow fields (`*_num`, `*_is_indefinite`) as `Optional`. Commit.
3. `src/fundtracker/normalize.py`: `parse_amount(text) -> (num, is_indefinite)`, `parse_date(text)` accepting ISO and `DD-MON-YYYY`, `parse_bool(text)` treating `true` as True and empty or missing as None, `join_name(first, middle, last)`, `is_entity(first, last, joined)`, `entity_stem(name)`, `fund_family_stem(issuer_name)`, `address_key(street1, zip)`, `none_to_null(text)` for the literal `None`. Pure functions, table-driven tests with the token lists from PLAN.md 7.2. Commit.
4. `src/fundtracker/edgar/formd_xml.py`: `parse_formd(xml_bytes, accession, cik_hint=None) -> FormDFiling` using `xml.etree`. Every element is optional; a missing element yields None, never an exception. Record `schema_version`. Golden tests per fixture asserting the values named in the reference's worked example for Axiaris and a hand-checked set of fields for each other fixture (read each fixture by eye once and assert what it says, do not assert what the parser returns). The two older-schema fixtures must parse without error, and their test must list which fields came back None so open question 1 can be closed with facts. Commit.
5. `src/fundtracker/db/schema.sql` and `src/fundtracker/db/repo.py`: create the raw tables and indexes from PLAN.md section 6 (not the derived tables yet), `connect(db_path)` applying the schema idempotently and setting WAL and foreign keys, `upsert_filing(conn, FormDFiling)` writing all six tables in one transaction with `INSERT ... ON CONFLICT DO UPDATE` on the natural keys, deleting and rewriting the child rows for an accession so a re-parse never leaves stale children, and read helpers `get_filing(accession)`, `filings_for_cik(cik)`. Tests on a temp database: load every fixture, load them all again, assert identical row counts and identical content; assert `filings_for_cik` ordering by filing date. Commit.
6. Close open question 1 in PROGRESS.md with what the older schemas actually differ in, append the session entry, and note any new open questions. Commit.

Constraints: no network in tests (the conftest fixture from Session 0 already enforces it); the fixture script is the only thing that touches EDGAR and it is run by hand. Stdlib only, no new dependencies. Keep the XML parser and the normaliser free of SQLite, and the repository free of XML, because WP2's TSV loader will feed the same dataclasses into the same repository.

Exit criteria: `pytest` green with no network; twelve fixtures committed with their README; loading all fixtures twice yields the same database; open question 1 closed with facts; six commits in the order above; PROGRESS.md updated.

## Session 2. Quarterly data set backfill (WP2)

Read PLAN.md (sections 4, 6, 7.5, 9 WP2), PROGRESS.md (decisions log in full, open questions 2 and 8), and docs/edgar-formd-reference.md section 5 first. This session loads the SEC's quarterly Form D data sets into the tables WP1 built, through the same dataclasses the XML parser produces. No daily index, no scoring, no UI.

1. `src/fundtracker/edgar/datasets.py`, discovery and download. `list_quarters(client)` fetches the data sets page, finds every link matching `form-d-data-sets/(\d{4})q([1-4])_d\.zip` (two URL prefixes are in use; do not hard-code either), and returns quarters sorted ascending with their absolute URLs. `download_quarter(client, quarter, dest_dir)` streams the zip to `data/datasets/{yyyy}q{n}_d.zip` through `EdgarClient.get` (not the cache; these files are large and the folder is the cache), skipping a file that already exists with non-zero size. Close open question 2 in PROGRESS.md with the earliest quarter found. Commit.
2. `src/fundtracker/edgar/datasets.py`, reading. `read_quarter(zip_path) -> Iterator[FormDFiling]` opens the zip, finds the six TSVs under their quarter folder, reads FORMDSUBMISSION and OFFERING keyed by ACCESSIONNUMBER, groups ISSUERS, RELATEDPERSONS, RECIPIENTS and SIGNATURES by accession, and yields one `FormDFiling` per submission with `source="dataset"`. Apply the value conventions from reference section 5 through the WP1 normalisers: `DD-MON-YYYY` filing dates, `YES`/`NO`, `true`/empty, `Indefinite`, `None`, trailing spaces on FILE_NUM, exemption list split on comma. Renumber child `seq` from 1 in SEQ_KEY order per the decisions log. Put the column-to-field mapping in one dict per table, and write a test that opens the fixture zip and asserts every header column is either mapped or in an explicit ignore list, so a new SEC column fails loudly. Commit.
3. Fixture and parity test. Write `scripts/make_dataset_fixture.py` that takes a real quarter zip, a list of accessions to keep, and a row count, and writes `tests/fixtures/datasets/<quarter>_trimmed.zip` holding those accessions plus that many other randomly chosen submissions (with all their child rows, same folder layout, same headers). Build one from 2015 Q2 keeping `0001635511-15-000001` (the AQR XML fixture) and one from 2010 Q2 keeping `0000919574-10-003893` (the 400 Capital fixture), each with 200 other submissions. Test: load the trimmed zip into a temp database, load the matching XML fixture into another, and compare the rows for that accession table by table. Fields allowed to differ are listed in the test with a reason each (expected: `source`, `loaded_at`, `file_num` and `schema_version` if the XML lacks them, and nothing else; if more differ, fix the loader or the parser so they agree, and record anything irreconcilable as an open question). Commit.
4. `src/fundtracker/ingest.py` and the `ingest_log` table. Add `ingest_log` to `schema.sql` if WP1 did not (columns per PLAN.md section 6). `backfill(conn, client, from_quarter=None, to_quarter=None)` lists quarters, skips any with an `ok` row in `ingest_log` under `source="dataset"` and key `{yyyy}q{n}`, downloads the rest, and loads each quarter inside one transaction using `executemany` batches rather than one `upsert_filing` call per filing if that is what it takes to finish in time; writes `ingest_log` with row counts and timing; on failure records the error and leaves no partial quarter behind. Test with the trimmed fixtures through a fake client: two runs, second is a no-op, `ingest_log` has one `ok` row per quarter. Commit.
5. `src/fundtracker/cli.py` with argparse and `python -m fundtracker`: `backfill [--from 2009q1] [--to 2026q3]` and `stats` (filings by source, by submission type, by fund type, quarters loaded, last `ingest_log` rows). Commit.
6. Run the real backfill once on this machine with `python -m fundtracker backfill`, then `stats`. Record in PROGRESS.md: wall time, database size, filings per source, and that 2026 Q3 shows 15,952 filings and 2,394 Hedge Fund offering rows (reference section 5). Append the session entry and any open questions. Commit.

Constraints: no network in tests; the real backfill is run by hand once in step 6. Stdlib only (`zipfile`, `csv` with `field_size_limit` raised, `io.TextIOWrapper` with utf-8 and `errors="replace"`). The loader must not import the XML parser, and the repository must not learn about TSVs. Memory: one quarter at a time, never the whole history.

Exit criteria: `pytest` green with no network; parity test passes for both quarters; full backfill completes in under 20 minutes and a second run is a no-op; `stats` reports the 2026 Q3 counts above; open questions 2 and 8 closed; six commits in order; PROGRESS.md updated.

## Session 3. Daily index ingest and catch-up (WP3)

Do not start until Session 2's exit criteria are recorded. Read PLAN.md (sections 4, 7.5, 9 WP3), PROGRESS.md (open question 7 in particular), and docs/edgar-formd-reference.md sections 2 and 3 first. This session makes the database current each night from the daily form index. No scoring, no UI.

1. `src/fundtracker/edgar/index.py`. `form_index_url(date)` builds `https://www.sec.gov/Archives/edgar/daily-index/{yyyy}/QTR{q}/form.{yyyymmdd}.idx`. `parse_form_index(text) -> list[IndexRow]` skips to the dashes line, reads the column offsets from the header line above it, slices each row, and returns rows with form type, company name, CIK, date filed and file name. `formd_rows(rows)` keeps `D` and `D/A` and de-duplicates on accession (open question 7), keeping the first CIK seen as `cik_hint`. `primary_doc_url(cik, accession)` builds the filing folder URL from reference section 2. Save a real `form.20261027.idx` trimmed to its header plus 40 `D` rows (including both GEF co-issuer rows), 10 `D/A` rows and 10 rows of other forms as `tests/fixtures/index/form.20261027.trimmed.idx`. Tests: offsets survive long company names, de-duplication keeps one GEF row, URL building matches the Axiaris folder. Commit.
2. `ingest.daily(conn, client, date)`. Fetch the index; a 404 writes `ingest_log` status `no_index` for that date and returns. Otherwise take the Form D rows, drop accessions already in `filing` (from either source), fetch each `primary_doc.xml` with `get_cached`, call `parse_formd(xml, accession, cik_hint, filing_date=date)`, `upsert_filing`, and count. A single filing that fails to fetch or parse is logged with its accession and the run continues; the `ingest_log` row records `ok` with an error count, or `error` if nothing could be loaded. Test through a fake client that serves the trimmed index and the WP1 XML fixtures for the accessions it names and 404 for a weekend date. Commit.
3. `ingest.catchup(conn, client, until=None)`. Start the day after the latest `ok` or `no_index` date in `ingest_log` for `source="daily"`; if there is none, start the day after the last filing date present from the data sets; if the database is empty, start 30 days ago. Walk every calendar day up to `until` (default: yesterday), skipping Saturdays and Sundays, calling `daily` for each; holidays come back as `no_index` and are recorded like weekends. Test: seed `ingest_log` with three days, delete the middle one, run catchup, assert exactly the missing days were fetched. Commit.
4. CLI: `ingest daily [--date YYYY-MM-DD]`, `ingest catchup [--until YYYY-MM-DD]`, and extend `stats` with the last daily date and the count of `no_index` days. Commit.
5. Run by hand: `python -m fundtracker ingest daily --date <yesterday's business day>`; run it again and confirm nothing is fetched; run `ingest catchup` to bring the database from the end of the last data set quarter to yesterday (several weeks of daily fetches at 5 per second; expect a few minutes per week) and record wall time and counts. Confirm the Axiaris filing (CIK 2158817) is present with filing date 2026-10-28, fund type Hedge Fund and exemptions 06c, 3C, 3C.1. Append the session entry to PROGRESS.md. Commit.

Constraints: no network in tests; stdlib only; `daily` must be safe to run twice and safe to run for a date already covered by a data set (it skips existing accessions and fetches nothing). Never fetch today's index by default; it is incomplete until the nightly build.

Exit criteria: `pytest` green with no network; the hand run loads every `D` and `D/A` filing for the chosen day and a second run fetches nothing; catchup refills exactly the missing days in the test and brings the real database to yesterday; the Axiaris check passes; five commits in order; PROGRESS.md updated.
